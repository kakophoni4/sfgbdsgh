# Проверка Excel через CRM

CRM принимает исходный Excel, передаёт его серверу парсера и показывает сохранённый прогресс. Проверки выполняются в существующей службе `FirmParserExport` на Windows. Telegram-сеанс и настройки прокси остаются на сервере парсера. Задания и ответы источников сохраняются в `data/company_checks/jobs.sqlite3`.

## Пользовательский сценарий

На странице «Парсер лавок» появился блок «Проверка базы компаний». Загрузите `.xlsx`, дождитесь завершения и нажмите «Скачать подробный Excel». Страницу можно закрывать. После перезапуска службы завершённые обращения к источникам сохраняются; незавершённое обращение выполняется повторно. Если служба остановилась после отправки ИНН, повторный запрос боту возможен: внешнее сообщение нельзя атомарно сохранить вместе с локальной БД.

Поддержаны заголовки «ИНН», «ИНН организации», «ИНН компании» в первых 50 строках каждого листа. ИНН проверяется по контрольным цифрам, хранится текстом. Повторы ИНН проверяются один раз, все исходные строки сохраняются. Ограничения: 20 МБ загруженного файла, 100 МБ распакованного содержимого, 10 000 строк данных, до 10 активных заданий в очереди. Доступ к заданиям ограничен пользователем CRM, который загрузил файл.

## Проверки и результат

Каждый ИНН проходит ЕГРЮЛ, БФО, Companium, Checko, КАД, ФССП, Федресурс, СБИС и ЗСК. При отсутствии подтверждённого ОГРН агрегаторы сохраняют явную ошибку; остальные источники продолжают проверяться. ЗСК для 12-значного ИНН помечается как неподдержанный текущим бот-модулем.

Это обращения ко всем доступным модулям, а не гарантия доступа к каждому реестру. Капча, блокировка, таймаут, отсутствие отчётности и недостающие подробности сохраняются явно. Полный список дел и публикаций может быть недоступен или ограничен первой страницей ответа. Признак банкротства в карточке не равен полной проверке ЕФРСБ, а счётчик сообщений не равен количеству залогов.

Excel содержит листы:

- **Компании**: одна строка на уникальный ИНН; статусы, данные регистрации, финансы по годам, счётчики рисков, ЗСК, категория, вывод и дата/ссылка/ошибка каждого источника.
- **Финансы по годам**: числовые показатели для сортировки по году и сумме.
- **Проверки источников**: ответы и ошибки каждого источника.
- **Подробные данные**: поля ответов источников.
- **Арбитражные дела** и **Публикации**: доступные записи с указанием полноты полученного списка.
- **Исходные строки** и **Ошибки импорта**: связь с загруженным файлом и причины пропуска.
- **Как читать**: значения пустых полей и ограничения источников.

На всех таблицах включены фильтры и закреплён заголовок. Идентификаторы хранятся текстом, суммы — числами, даты — датами. Пустая сумма не заменяется нулём. При расхождении счётчиков показан максимум, а оба значения и конфликт сохранены рядом. Исходный статус ликвидации не стирается ответом другого источника. Формулы из входного файла не исполняются в итоговом отчёте.

## Установка на Windows-сервер

Разработка и тесты выполнены локально. На удалённом сервере этот код ещё не установлен.

Изменения ещё не опубликованы в GitHub. Устанавливайте приложенный пакет; обновление со старой ветки GitHub может вернуть прежний код.

Распакуйте пакет `company-checks.zip`, например в `C:\company-checks`. Запустите PowerShell с правами администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\company-checks\parser-update\deploy\install_company_checks.ps1 -Target C:\firmy
curl.exe --max-time 10 -sS http://127.0.0.1:8788/healthz
```

Установщик копирует только файлы из манифеста и перезапускает `FirmParserExport`. Он сохраняет учётную запись, пароль, триггеры и настройки существующей задачи. Задача `FirmParser` не перезапускается. Повторно запускать старый `register_export_server.ps1` не требуется: он может вернуть интерактивный вход.

Используется тот же порт 8788 и тот же `LAVOK_INGEST_TOKEN`. Существующее правило firewall должно разрешать CRM доступ. Прокси используются прежними модулями только для Companium/Checko. Секреты, `.env`, Telegram-сеанс и база в пакет не включены.

Опциональные параметры `.env` парсера:

```dotenv
COMPANY_CHECK_SOURCE_TIMEOUT=180
COMPANY_CHECK_PAUSE=2
```

Таймаут ограничивает одно обращение к одному источнику, включая его внутренние повторы. В Windows дочерние процессы помещаются в Job Object и завершаются при остановке службы. Общий mutex не допускает параллельного использования Telegram-сеанса с плановым парсером. Большая база может обрабатываться часами; очередная плановая задача пропускается, пока проверка базы удерживает mutex. Ручной запуск `run_parser.py` вне `run_job.ps1` этот mutex не использует и не должен выполняться параллельно.

## Обновление CRM

В пакете `crm-update` лежат изменённые/новые исходники CRM с сохранённой структурой папок, а в `crm.patch` — изменения для существующего Git checkout. Предпочтительно проверить `git apply --check /путь/к/crm.patch`, затем `git apply /путь/к/crm.patch`. Если проверка не проходит, нужно перенести изменения с учётом актуальной версии CRM, а не заменять её файлы целиком. Установите обычные зависимости проекта, пересоберите frontend (`npm ci`, `npm run build`) и перезапустите backend стандартным способом вашего деплоя. Миграция БД CRM не требуется: задания хранятся на Windows-сервере.

Настройки backend CRM:

```dotenv
LAVOK_PARSER_CHECKS_URL=http://146.19.125.73:8788/lavok/checks
LAVOK_PARSER_INGEST_TOKEN=<существующий токен из .env парсера>
```

Если `LAVOK_PARSER_CHECKS_URL` не задан, адрес определяется из origin существующего `LAVOK_PARSER_PULL_URL`. Токен хранится только в backend; в браузер не передаётся. Обновите фактический IP/DNS, если сервер изменился.

## API для CRM

- `POST /api/v1/lavok-parser/checks`: multipart `file`, ответ 202 и идентификатор задания.
- `GET /api/v1/lavok-parser/checks`: последние 30 заданий текущего пользователя.
- `GET /api/v1/lavok-parser/checks/{id}`: этап, ИНН, счётчики и прогресс.
- `POST /api/v1/lavok-parser/checks/{id}/cancel`: остановка с сохранением результата.
- `POST /api/v1/lavok-parser/checks/{id}/resume`: продолжение и повтор ошибочных/частичных проверок.
- `GET /api/v1/lavok-parser/checks/{id}/result.xlsx`: готовый подробный Excel.

Все CRM endpoints требуют обычной авторизации и права `PARSER_READ`. CRM скачивает результат с Windows-сервера частями через HTTP Range и проверяет размер и ETag, чтобы не получить смешанный файл при перезаписи.

## Проверка после установки

Сначала загрузите небольшой файл с 2–3 компаниями. Убедитесь, что прогресс меняется, блокировки источников отображаются как ошибки, файл скачивается и фильтры работают. Проверьте ЗСК на ответах реального бота: ответ должен содержать отправленный ИНН либо быть явным ответом на отправленное сообщение. Для большого исходного файла проверено чтение всех 2 595 ИНН; массовые сетевые обращения локально не запускались.
